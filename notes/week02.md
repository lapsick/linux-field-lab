# Лабораторна 02 · Health report

## Скрипт

`scripts/health.sh` має право на виконання, shebang `#!/usr/bin/env bash`
і `set -euo pipefail`. Приймає рівно один аргумент; за помилки використання
повертає 2. Шляхи та аргументи взято в подвійні лапки, тому каталог із пробілами
обробляється правильно. Назва звіту містить timestamp і PID запуску.

Звіт містить результати `date -Is`, `df -h`, `free -h`,
`ps -p 1 -o pid,comm`, `ip -br addr`, `ss -lntup`.
Скрипт не читає змінні середовища для звіту та не збирає секрети.

Очікувані помилки обробляються через `if …; then …; else`.
Код невдалої команди зберігається як `status=$?` першою командою в `else`.
Для команд звіту він повертається без змін. Помилки створення каталогу
або відкриття файлу повертають 1 згідно з умовою; початковий код зазначається
у stderr. Не використовується конструкція `if ! command; then status=$?`,
бо вона зберегла б код інверсії, а не початкової команди.

У перевірюваному блоці Bash не покладається на `set -e`: команди явно
з'єднано через `&&`, а помилка запису заголовка також повертається явно.
При невдачі частковий звіт залишається для діагностики.

## Два запуски

З кореня проєкту виконано:

```bash
./scripts/health.sh "evidence/test reports"
echo $?
# 0

./scripts/health.sh /proc/field-lab-no-write
echo $?
# 1
```

`echo $?` виконано безпосередньо після кожного запуску.
Повний вивід збережено у `evidence/health-success.txt` та
`evidence/health-failure.txt`. Успішний звіт:
`evidence/test reports/report-20261021-143027-42597.txt`.

Перший запуск у sandbox не мав доступу до netlink: `ip` повернув 1.
Це також підтвердило обробку помилки команди. Його частковий звіт:
`evidence/test reports/report-20261021-143012-6.txt`.
Успішну перевірку повторено поза sandbox з дозволом користувача.
Час у назвах файлів визначає середовище виконання командою `date`.

## Фоновий процес і SIGTERM

```bash
sleep 120 &
pid=$!
ps -p "$pid" -o pid,comm
kill -TERM "$pid"
wait "$pid"
echo $?
ps -p "$pid" -o pid,comm
```

Результат у `evidence/sigterm.txt`: PID 3, команда `sleep`;
`wait` повернув 143 (128 + номер SIGTERM 15).
Після очікування `ps` показав лише заголовок: процес завершився.
`$!` дає PID останнього фонового процесу, а `wait` дозволяє перевірити
завершення без гонки між надсиланням сигналу та перевіркою.

## Перевірка

`bash -n scripts/health.sh` завершився успішно.
